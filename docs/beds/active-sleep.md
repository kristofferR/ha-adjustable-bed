# Active Sleep

**Status:** Not yet tested on hardware. Requires an existing authentication ID.

**Credit:** Reverse engineering by [kristofferR](https://github.com/kristofferR/ha-adjustable-bed)

## Known Models

INTIME, ACTIVE_SLEEP, INTIME_COMFORT, INTIME_1000 and ACTIVE_SLEEP_BED_FMC.
Controls appear only after the bed reports its model, presence and motor ranges.
Unknown models remain unavailable for movement.

| Feature | Supported |
|---|---|

| Presets | Ten app templates, with model and range checks |
| Memory | Local app template save/reset; no on-bed memory programming |
| Bed Settings | Supported motor locks and normal/fast movement |
| Mattress | Five six-zone templates, ventilation and Fukatto |
| Sensors | Reported heart and respiration rates when an analyzer is present |

| Massage / Lights | No |

## Choosing a profile

Select **Active Sleep (Paramount)**, not Paramount Bed Operation. These apps use
different GATT services and packet formats. An exact, case-sensitive `Active`
Bluetooth name prefix suggests the app, but cannot select a model.

### Packet Format

Frames contain an opcode, payload length, payload and XOR of every preceding
byte. Normal control uses write-with-response and notifications on the same
characteristic. Queries are writes, not ATT reads. Ordinary control frames fit
one write. The optional split builder uses 20 bytes first, then 19-byte chunks
prefixed `8F`; it is not needed by the supported controls.

### Responses

`01` carries the serial. `02` reports analyzer/bed/mattress presence, model and
mode. `04` accepts authentication results 0 or 2. `31` supplies signed ranges
and supported lock bits. `32` reports signed positions, current locks, speed and
failure code. `34` echoes a movement selector and positions. `41` carries six
pressure nibbles, mode, sound, ventilation, Fukatto, remaining time, busy flags
and failure code. `33` and `42` acknowledge settings, followed by readback.

`22` carries a sequence, eight graph samples, patient-status byte, respiration
and heart bytes. Respiration uses truncation of `raw * 0.2`; heart is unscaled.
Both report unknown for 0 and 252–255, and repeated sequences do not republish.
Uninterpreted bytes and pressure codes are diagnostic values, not controls.
These are bed-reported values, not clinical measurements.

### Execution

Commands repeat at the shipped 200 ms fallback interval. Manual start waits
50 ms; held presets for models 1, 3 and 4 wait 250 ms. A matching movement reply
must arrive within 50 ms. Release sends the existing STOP after 200 ms with a
fresh cancellation event, on the original connection only. A missing or
cancelled reply blocks further commands until reconnect, preventing ambiguous
late replies from authorizing another movement. Settings and mattress writes
use read/modify/write/readback without automatic replay.

Height lowering and targets retain the app's warning check. Check clearance
and the area beneath the bed, then use **Acknowledge bed height warning** before
retrying. Acknowledgement belongs to the current connection. The fallback
threshold is 28 cm for INTIME_COMFORT, 36 cm for INTIME_1000 and 31 cm otherwise,
with the app's tilt geometry and warning exemptions. The later warning band
requires two seconds without a position change. Reached targets wait a separate
one-second interval before release. Hardware still enforces its own limits.

## Active Sleep profile

### Detection / Setup

Provide an **existing** 16-character ASCII authentication ID from your own
registered setup. This integration cannot issue or retrieve it, register an
account, or log in to the vendor. Leave the optional field blank to configure
it later; control remains unavailable. Other lengths and non-ASCII IDs need
additional encoding evidence. The ID is redacted in diagnostics and command
traces. Do not paste it into an issue or support log.

Notifications start before serial/spec/authentication queries. Control requires
normal device mode and successful authentication, followed by fresh limits and
positions. Pairing two physical beds uses Home Assistant's independent links;
there is no protocol side-address byte. Held service requests validate every
target's capabilities, locks and height warning before either target moves.

### Controls

Head and legs provide movement and feedback sliders. Height is available only
with height-lock support, and tilt only for reported models 3 and 5. Combination
controls use the shared head/leg selector. App bed templates repeat target
frames while held; unsupported axes, locks or out-of-range targets reject the
whole template. Template 10 is offered only for FMC. Template save/reset changes
Home Assistant's local copy and never writes bed memory.

Mattress controls query current state first and preserve unrelated sound and
Fukatto flags. Recalling a template disables ventilation, as in the app. Sound
has no user setter. Manual/recommended hardness entry remains unavailable until
its user range and recommendation inputs are known. Enable **Realtime sensor monitor** to query at the app's 100 ms interval while
the connection is idle. Other state refreshes once per second. The raw graph
samples are diagnostic; Home Assistant provides its own sensor history view.

### Notes

The app can receive replacement templates and timing constants from its server;
Home Assistant uses the shipped fallback data only. Network provisioning,
accounts, cloud schedules, firmware updates and audio analysis are outside this
integration. No light, massage motor, lumbar/neck motor, side-addressing or bed
calibration command is defined here.

### Analysis provenance

Based on Active Sleep 1.3.5 (11136), `com.paramount.bed`. Static coverage remains
partial and physical behavior is unverified. Users can supply redacted logs
