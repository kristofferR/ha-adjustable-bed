# BERUN

**Status:** Not yet tested (hardware and ATT behavior unverified)

**Credit:** Reverse engineering by [kristofferR](https://github.com/kristofferR/ha-adjustable-bed)

## Known Models

Receivers used with the BERUN app, with Bluetooth names starting with `okin`
or `smartbed` (case insensitive). These names are shared with other apps.

## Features

| Feature | Supported |
|---------|-----------|
| Motor Control | Head/back and foot/legs |
| Position Feedback | No |
| Presets | Flat, Zero gravity, Memory, TV, Read and Anti-snore |
| Memory Presets | Memory is a named preset; no numbered slots or separate save action |
| Massage | Toggle, head and foot intensity cycles, mode cycle; timer cycle except v7 |
| Lights | Toggle button except v8 |
| Clock and alarm | Local bed clock; one alarm for massage or Memory, repeated daily |
| Status | Reported massage levels, timer index, mode and alarm |
| Paired beds | Two separate Bluetooth receivers; no single-address side selection |

## Protocol Details

Four versions use existing [Keeson](keeson.md), Okin ORE and
[Okin N-frame](okin-nframe.md) encoders. Each version keeps its own command
catalog, even where bytes match.

### Packet Format

- v6: `E6 FE 16 <little-endian 32-bit word> 00 checksum`, complement checksum over all preceding bytes.
- v7: `A5 5A checksum 00 00 <big-endian 16-bit opcode>`, complement checksum over the four bytes after the checksum.
- v8/v9: `05 02 <big-endian 32-bit word> 00`, without checksum.

### Write Mode

The app leaves the discovered characteristic's write mode unchanged. HA uses
acknowledged writes when advertised, otherwise writes without response. The
roles below are selected independently of the advertisement version. If a
receiver exposes several matching roles, the last role in stable GATT order
wins. Writes and deferred cleanup remain on the connection that admitted them.
Subscribe before sending the local bed clock once; there is no authentication
handshake.

## Detection / Setup

1. Choose **BERUN app** explicitly. The common names only offer it as a candidate.
2. Confirm version 6, 7, 8 or 9. Advertisement data prefills this choice when
   available; manual setup requires a choice.

The active Android parser retains manufacturer company-id bytes. HA reconstructs
that data in ascending company-id order: initial `4F 4B` selects v7 first;
otherwise `44 4F 54 00 01` at offset 2 selects v8, `44 4F 54 00` selects v9,
and other accepted names select v6. These signatures do not select BERUN over
another app. A two-address pair keeps each receiver's version independently.

## Commands

### Motor Control

Head and foot move while held, with one STOP on release. The common covers
provide finite taps and the card supports renewable holds.

### Presets

Flat and the five named presets use the same held execution. A long preset hold
continues recalling that position. The app's “Memory saved” toast at 5.5 seconds
has no separate save frame or acknowledgement, so HA offers no save action.

### Memory

Memory is one named held preset. It does not establish numbered memory slots
or physical programming.

### Massage

Click once for toggle, head cycle, foot cycle or mode cycle. v8/v9 query status
100 ms after a massage click. v7 has no working timer-cycle command.

### Lights

v6, v7 and v9 have a one-shot toggle. v8's Light action fails before writing
in the app and is unavailable in HA.

### Clock and alarm

The clock uses `E7 80 01` with year minus 1900 and zero-based month on v6/v7,
or `07 04` with year minus 2000, one-based month and Sunday-zero weekday on
v8/v9. Both use Home Assistant's local time.

Use **Set alarm** with `wake_action: massage` or `wake_action: memory_1` for
the app's Memory preset. The alarm repeats on all seven days; a weekday
selection is unavailable because the app has no day picker. Turning it off
writes the all-zero alarm. v6/v7 use `ED 80 03` records; v8/v9 use `07 05`.
The action sends SET and query at 0 and 300 ms, then SET at 600 ms, and waits
through the final 300 ms. Alarm query alone sends twice, 300 ms apart.

## Position Feedback / Notifications

No motor position or angle data is reported. Notifications update only massage
and alarm state. Each event is parsed independently, without fragment reassembly
or incoming checksum validation. Truncated or invalid numeric fields are ignored
instead of publishing the app's NaN values. v6/v7 decimal-nibble parsing is
preserved. v8/v9 apply their own intensity and timer-index scaling. The timer
index is the app's zero-based 10/20/30 minute selection, separate from the
Massage binary sensor. Alarm-off replies retain the previous alarm details.
A5/5A replies are log-only. Reconnect clears reported state.

## Command Timing

Held controls refresh every 200 ms, with one immediate STOP on release, including
cancellation. Clicks do not send a motion STOP. Pending writes finish before
release; an expired connection cannot send its old query, clock or STOP through
a replacement connection. Home Assistant supplies command scheduling and safe
cleanup for interrupted holds.
