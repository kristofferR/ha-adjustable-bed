## Known Models

- Prime, Lombar and Infinity are the app's layout choices. Their physical model mapping is unverified.
- The Bluetooth name selects the app's transport independently of its layout.

### Packet Format

BOX15 uses the shared [Keeson](keeson.md) E6 frame, with a zero trailing byte before its complemented byte-sum checksum. BOX1220's native actions use the [Okin ORE](okin-nframe.md) A5 5A encoder; its other actions use the same unchecked 05 02 carrier as BOX24. The final zero in that carrier does not establish side selection.

### Write Mode

The selected branch fixes both GATT roles and response mode. Missing roles or unsupported properties refuse the connection. Notifications or indications use Home Assistant's Bluetooth stack. No startup commands, reads or bed authentication exchange are required.

## Detection / Setup

Choose **Restonic app (Prime / Lombar / Infinity)**, then the layout and BLE branch. The app chooses BOX24 for the case-sensitive `Smartbed` prefix, BOX1220 for the case-sensitive `BLE` prefix, and BOX15 for every other nonempty name. These broad names do not identify Restonic hardware, so Home Assistant requires explicit selection and does not discover every named Bluetooth device as a bed.

Each side of a two-address pair owns its own layout and branch. One-address split control is unavailable.

### Memory

Memory A recalls `m1`. Prime's memory-B picture dispatches anti-snore; Lombar's dispatches lounge. Home Assistant names those actions by their function. There is no separate programming command or save button. A prolonged recall's firmware interpretation is unverified.

### Massage and Lights

These are action buttons without assumed on/off, intensity, timer or light state. The BOX24 and BOX1220 fallback bytes for neck and lumbar are identical. Their massage toggle and timer bytes are also identical; Home Assistant retains both app-labelled controls.

## Position Feedback / Notifications

BOX15 supports its retained F4 FE 16 fragment, ED80 and length-selected replies. BOX24 supports A50C and A50B0E; BOX1220 subscribes but has no state dispatch. Raw offset fields are available only in protocol diagnostics, with no sensor entities or inferred units. They clear when the connection ends. They do not create position sliders, alarm controls, inferred brightness or measured state.

The BOX24 A50B0E low nibble is divided by two using integer division, including odd values. Short packets are ignored rather than reproducing the app's indexing errors. Fragment retention is bounded and restricted to the current link. Replies are not command acknowledgements.

## Command Timing

The generated profile table lists the refresh and STOP cadence. Every active action sends immediately and repeats while held. Ordinary action-button presses hold for one refresh interval; motor presses use the configured pulse count at the app's fixed cadence. `hold_control` and timed movement set an explicit duration; the dashboard can renew a hold lease.

Release and public STOP send the two proven STOP frames. An expired or cancelled command waiting for GATT sends no frame. Once a write starts, cancellation waits for bounded write settlement before cleanup. Refresh and cleanup stay on their original connection; a replacement link never receives an old action or STOP.

## Notes

The lock and pair pictures have no active press command. Network provisioning, account services, Wi-Fi control and companion functions are outside this BLE integration.
