### Framing and checksum

Controls contain a B0 header, length, fixed prefix, little-endian word and
additive low-byte checksum. The fixed prefix does not establish side addressing.
Identity replies contain a B1 header, length, zero, six persisted random bytes
and the same checksum. This is an identity exchange, not cryptographic authentication.

### Responses

The exact identity challenge causes a single reply. Unsolicited count records
carry a signed index and signed little-endian count, with a type mask and
checksum. The integration rejects short records and negative/out-of-range
indexes safely; it retains the app's first-record handling of trailing data.
No read or query frame is sent. Raw counts and the app's image bins remain
diagnostics, because their physical scale is unknown.

### STOP and release behavior

Release and Stop end command refresh. No separate release or global STOP packet
is defined. Device watchdog latency is unknown. Home Assistant stops refreshing
on cancellation, disconnection, replacement or timeout and never moves a queued
write to a replacement connection.

## Profiles

### AVEK

**App:** [AVEK Ergo System](https://play.google.com/store/apps/details?id=com.moteck.TBA4AK) 2.0.2, `com.moteck.TBA4AK`

**Status:** Not yet tested on hardware

#### Setup

No model, remote code, PIN or motor-layout question. Discovery follows the
case-sensitive prefixes in the generated table. The live service must supply
the fixed write and notify characteristics. The app inherits its write mode;
Home Assistant selects from live GATT properties, preferring writes without a
response when advertised, including dual-property receivers. Write-only
receivers use a response. The app identity is random and persisted across reconnects.

#### Controls

Shoulder and Hip buttons adjust firmness. A–D preserve the app's labels; they
are not side selectors. Save sends only its standalone command, without an
invented slot combination. Save and Initial start disabled in the entity registry.
Save has no held gesture because the card asks for confirmation.

#### Timing

All ordinary buttons start immediately and refresh while held. A tap uses
**Movement per tap** to choose its finite duration. See the generated table for
cadence. Each next refresh is scheduled from the actual dispatch of the previous
frame, so a delayed writer does not catch up with a burst. Held controls are
serialized, without concurrent-axis composition.

Initial waits cancellably for this connection’s identity reply, with the separate
Home Assistant readiness timeout in the generated table. Only after that reply
does its independent movement window begin. Initial ends when both reported
Shoulder/Hip counts reach the profile endpoint
or the Home Assistant limit expires. Unknown counts never masquerade as endpoint
reports. The app's own waiter requests cancellation but only cancels if its
connection and recognition flags remain true when handled; its sender has no
independent deadline. The Home Assistant limit is an integration safety bound,
not a proven bed watchdog or an unconditional app transmission bound. Initial
does not imply a conventional Flat preset.

#### Notifications

Identity replies are redacted from command traces and debug payloads.
Identity recognition records only that the reply was sent in this connection,
not a device acknowledgement. Count state and recognition clear with the link.

#### Services

Use the shared held-control action for the eight ordinary firmness/A–D controls.
Save and Initial are available through their button entities. Generic slot
programming, Flat, position targeting and side selection are unavailable.

#### Evidence

Based on AVEK Ergo System 2.0.2 (210722202).
