### Framing and checksum

Outbound packets are header `40`, command, payload length, payload, then the XOR
of every preceding byte. Integer payload arguments are unsigned bytes. Empty
queries, controls, registration and settings are respectively 4, 9, 12 and 16
bytes. There is no sequence number or application encryption.

### Responses

| Reply | Payload | Interpretation |
|-------|---------|----------------|
| 01 | One byte | Session state; 6 is ready |
| 02 | Fourteen bytes | Full-frame offsets 9/10: height bounds, 13: capability mask |
| 03 | Twelve bytes | Four settings bytes, memory 1 H/L/Z/T, memory 2 H/L/Z/T |
| 04 | Seven bytes | Operation, head, legs, height, raw tilt, RSSI, uninterpreted byte |
| 05 | No interpreted fields | Settings acknowledgement; read settings next |
| 06 | One byte | Raw registration result; no invented success-code mapping |

Unknown device fields remain raw. RSSI is present only when its high bit is set,
then `(value & 0x7f) - 100`; otherwise the preceding RSSI remains. Serial bytes
become lowercase hexadecimal, not text. A saved height of 255 remains unchanged
on recall; constrained head/leg values clamp to their local limits. Tilt is saved
and recalled unchanged, with no independent tilt movement command.

HA drops foreign, unknown or truncated replies and verifies the known payload
length. The app does no incoming checksum validation, so HA does not invent an
incoming checksum contract. A trailing byte is left uninterpreted.

### STOP and release behavior

Neutral is the operation-zero control in the generated table. Every movement,
including recall and concurrent push, sends it in `finally` with a fresh cancel
event. A whole-side STOP also sends neutral. HA sends release immediately after
cancellation or failure, including when no reply arrives.

The shipped app chooses neutral for a later matching-reply cycle. Its missing
reply retry can retain stale movement and resets its retry counter. HA never
replays a movement because its reply is missing. It fails the request and sends
neutral. Physical stopping latency and any firmware watchdog remain unverified.

### Vectors

`tests/paramount_vectors.py` freezes all eighteen outgoing literals and the six
response fixtures from the accepted artifact. `tests/test_paramount.py` checks
encoding, parsing, capability combinations, startup, cancellation, readback,
settings preservation and memory clamping. This framing has no equivalent codec
in the existing v5 families, so it has its own codec and typed profile.

## Profiles

### Bed Operation

#### Setup

Use the receiver's registration instructions, close its app, and let HA discover
it. A connect-wait advertisement makes startup send the fixed registration request.
The bed transitions by disconnecting and advertising registration mode; HA retries
its connection. The **Enter registration mode** button exposes the same request.
It may disconnect a working session.

The app requests Android OS bonding, but neither its device-info flag nor these
packets prove a hardware bond requirement or negotiated security. HA does not
mark a bond verified from them. If the bed requests bonding, use HA's supported
Bluetooth pairing flow and a host adapter that supports it. Proxy setup and
optional bonding keep their existing HA behavior.

Startup subscribes before observing readiness, then reads capabilities, settings,
neutral status and the binary serial characteristic when present. Non-ready
states repeat observation within HA's bounded setup deadline. No capability is
invented for an unrecognized layout mask; its individual bits still apply.

#### Controls

The receiver bits gate motor covers, degree sliders and two memories. Slider
seeks use the app's one-second pulse, independently of the native tap duration. Head and
legs use their named axes; height has its own cover and cm sensor. Linked motion
has its own cover. Concurrent Push remains the app's named action, without an
assumed axis combination. There are no split-side selectors.

Use the speed and prohibition selects to change bed settings. Changes first read
current settings, preserve every unrelated byte and both memories, then compare
all readback fields. HA fails a mismatch without automatically repeating the
write; it does not copy the app's collision-prone XOR-only confirmation.

Per-axis minimum, maximum and enable controls are local preferences, persisted
per bed. Disabling an axis prevents its manual movement. Limits select neutral
from feedback and constrain recall targets. Linked motion uses head feedback.
Linked movement is unavailable while an enabled head or leg range is narrowed,
including after restoring preferences. These are software bounds, not physical
safety interlocks. The duration select
chooses hold or 1–4 seconds for native actions. A hold-mode tap uses HA's bounded
one-second pulse; the dashboard's pressed gesture uses the renewable hold service.
The app's touch debounce and feedback-driven limits do not certify a firmware
watchdog. The app's UI hysteresis is not a new wire command.

#### Timing

See the generated profile table. Each movement refresh follows its matching reply
and the app's response delay. HA bounds the whole movement, including slow replies.
Idle live-link queries send neutral and request settings every fifth reply, in
HA's preemptible query lane. They never connect or prolong the idle deadline.
The app's idle default is 30 seconds; HA uses its configurable integration idle
setting (40 seconds by default), with Disconnect After Command available.

#### Notifications

Replies update positions, settings selects and diagnostic sensors. Disconnect
invalidates live posture and writable settings. A callback from an older
subscription cannot satisfy a new session. Capabilities are persisted for entity
identity and refreshed on every connection.

#### Services

Standard movement, `timed_move`, `hold_control`, `goto_preset` and memory-save
actions use HA's normal command serialization and cancellation. `hold_control`
also accepts `head_up/down`, `legs_up/down`, `height_up/down`, `gearing_up/down`,
`concurrent_push` and `memory_1/2` when the corresponding capability exists.
There is no general absolute-position packet inferred from memory targets.

#### Evidence

A07's accepted Bed Operation artifact defines one P1 wire family across the
current registration and ongoing-operation transports. Static vectors cover its
complete outgoing command set; hardware validation remains for beta/release users.
