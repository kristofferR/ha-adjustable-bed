# Personal Comfort

**Status:** Not yet tested

**Credit:** Reverse engineering by [kristofferR](https://github.com/kristofferR/ha-adjustable-bed)

## Known Models

Personal Comfort air units ANM V3, ANM V5 and RA, with a separately configured
Malouf, Reverie or Reverie V2 base. The base model is an explicit setup choice.
An air unit is not a second base in a combined pair.

## Features

| Feature | Supported |
|---------|-----------|
| Firmness | Native left/right values and immediate targets, 5–50 |
| Motor Control | Base head/feet; pillow on selected models and routes |
| Position Feedback | No base positions or angle seeking |
| Memory Presets | Two on Malouf and V2; none on Reverie V1 or air units |
| Massage | Model-specific head/foot, pattern and stop operations |
| Lights | Toggle on Malouf/V1; on/off with initial read on V2 |
| Alarm | No |

ANM V3 notifies on FFE0/FFE4. RA uses separate left/right pressure read and write
characteristics in its service, plus Device Information firmware 180A/2A26.

### Framing and checksum

ANM V3 uses ten bytes: 55, 04, operation, head/foot, middle, 00, 00, side,
low-byte sum of 89 plus operation and the three variable fields, AA.
Left uses side 3 and both target fields; right uses side 2 and middle only.
ANM V5 uses LF-terminated ASCII. Targets scale to
`floor((clamp(target, 5, 50) - 5) * 66 / 45)`.
RA sends three low bytes: twice the target, 15, 15.
Malouf uses the [Richmat codec](richmat.md). Reverie V1 XORs its packet bytes,
except its two-byte lighting toggle. V2 writes one byte to a feature-specific
characteristic.

### Responses

V3 reads operation at byte 2 and left/right firmness at bytes 5/4. It waits for
ready before dispatching a captured target; busy retries are bounded. An
acknowledgement is answered once, followed by a current-value query after 200 ms.
V5 requires `RET>SP>` followed by seven hexadecimal pairs. Its second status
determines adjustment completion. Firmness scales back with
`floor(5 + 45 * clamp(pressure, 0, 66) / 66)`.

RA refreshes both sides in the background after firmware is known. A firmness
action hydrates and reads back only its requested side. Exactly `71RU2265.00`,
`71RU2265.01`, `71RU2265.02` and `71RU2265.03` use byte 0 unchanged; all other
firmware strings use its integer half. Two-byte big-endian status indicates
idle, inflation/deflation, error or unknown. Zone names in status do not add
independent zone controls. Truncated replies are ignored; no packet reassembly
or extra checksum is assumed.

### STOP and release behavior

V3 and RA have no STOP command. Cancelling a pending operation stops further
writes from Home Assistant; it does not stop the pump. V5 STOP is
pump-wide. Malouf release ends its 200 ms refresh without an extra packet.
V1 releases with its global frame. V2 releases the captured motor characteristic.
Cleanup retains the physical connection and runs with a fresh cancellation event.

## Profiles

### Personal Comfort

#### Home Assistant setup

Choose **Personal Comfort app**, then the air unit or base controller supplied with
the bed. Air names beginning `2618` or `2816` use ANM V5 only within the ANM
discovery route. An RA service takes precedence. Generic Device Information or
battery services alone do not identify this app. Shared base services offer a
candidate; they do not change existing entries automatically.

Configure each physical base separately and select its model. **None** exposes
no base controls. Combine compatible base entries for left/right control; each
side keeps its route and model. One-address side selection is unsupported.
Air numbers already name their native side. Reconfigure changes the saved route
and model using the integration's standard setup flow.

#### Commands and features

Use normal movement, memory, lighting and massage entities. Saving a memory
requires explicit confirmation in the dashboard card. A mixed pair containing
Reverie V1 rejects a both-side memory action before either base writes.

The [sequence action](../SERVICES.md#personal_comfort_sequence) runs head then
foot massage 500 ms apart. Flat and anti-snore peer-foot sequences move the
selected base to the preset and lower the other base's feet for 30 seconds.
Both physical participants are reserved and validated first. These sequences
require concurrent connections when both bases participate.

#### Timing and release

V3 initial queries retry every second until firmness arrives. Its preparing
indicator clears after five seconds without fabricating a STOP. V5 queries send
channel 0 twice, 200 ms after each successful write, then request pressure.
An active adjustment polls every 500 ms; preparing expires after three seconds.
RA retries firmware reads after 200 ms and failed pressure reads after 500 ms;
a setter refreshes pressure after five seconds.

After reconnect, a firmness request waits up to 10 seconds for the selected
side's measured value. Home Assistant bounds each foreground firmness action
to two minutes if readiness, completion or pressure replies stop arriving.
These are software wait limits, not firmware timing or automatic pump STOPs.

#### Notes

No alarm, app-local firmness memories, local side/sync selectors, raw developer
probes, unused lumbar/combined commands or network/account features are exposed.
All physical effects, GATT properties, firmware variants and release behavior
still need testing on actual hardware.
