## Known Models

Choose the BLE type and motor layout shown in the Alya app. Physical bed model mappings are unknown. HPS command bytes are retained for protocol evidence, but HPS controls are unavailable until their physical function is established.

## Features

Movement, preset recall, massage, light toggle and weekly alarms depend on the explicit layout below. There is no position feedback or memory programming.

## Detection / Setup

Search for **Alya Smart Furnishing** and select the exact app BLE type and motor count. Shared UUIDs and raw Android scan offsets cannot identify this app safely in Home Assistant. Setup checks the selected layout's exact write and notification roles when the bed is reachable. An offline check remains inconclusive; runtime repeats the same check before control.

Only DACHENG five-motor offers side A / B / both. For separate left and right entities on its one Bluetooth address, open Configure and choose **Add Left, Right and Both controls**; splitting it again restores the standalone settings. A maps to the logical left child, B to right; verify this convention on your bed. CB24 five-motor always addresses both. Two-address entries retain their own layout and side settings. BLUETOOTH layouts also ask whether the app shows a massage page; its advertised identity can disable that page.

## Protocol Details

A single app spans the [ORE codec](../../custom_components/adjustable_bed/codec/okin_ore.py), [Keeson codec](keeson.md) and [Okin N-frame codec](okin-nframe.md). Its own typed profiles select commands and timing. This is an app guide across codecs, rather than a new wire format.

### Write Mode

The APK retains Android's characteristic default. HA selects the ATT mode from the actual characteristic properties; no inferred write mode or alternate characteristic is forced. Notifications require the exact notify role, not an indication-only characteristic. There is no proprietary authentication or connect-time query.

### Memory

Memory actions recall only. The app's save-named success callback sends no programming frame. Use a deliberate bounded hold or renewable gesture for presets; completion is never claimed from a write or an uncorrelated ACK.

### Massage and Lights

Use the massage timer select for 10, 20 or 30 minutes, and the intensity sliders for levels 1 to 3. The selected layout determines whether one combined intensity slider or separate head and foot sliders exist. No Off timer option or level zero is inferred. These settings remain unknown in HA; received fields stay in the diagnostic report, without guessing an aggregate level or which side a report describes. Other massage adjustments use the shared catalog buttons. All adjustments require a current-session report showing active head or foot massage. Toggle-only commands do not claim on/off state. Light on/off requires an actual current-session light report; toggle remains available. Refresh reports explicitly; no polling runs while idle.

### Clock and Alarms

Use `adjustable_bed.sync_clock` for HA local civil time, and `adjustable_bed.set_alarm` for the complete weekly record. Enabling an alarm first synchronizes HA local civil time, sends the alarm after 300 ms, and queries it at 600 ms on the same BLE connection. Disabling writes only the disabled record. The shared action accepts weekday names, such as `monday` and `friday`. The app's Sunday-based bits and repeat flag are encoded per route; an empty weekday list retains that route's no-weekday convention. Available wake modes depend on the layout. No previous UI placeholder or cached alarm is read to construct a write.

## Position Feedback / Notifications

No motor position, angle or percentage reports exist in this app. The default-disabled **Alya received report** diagnostic exposes only received fields, including raw massage levels, minutes, wave, alarm fields and uncorrelated ACK code. It clears on disconnect. It is not a physical-position or completion sensor.

P1 preserves Java's signed opcode arithmetic: canonical high low-bytes can miss scalar branches. Invalid headers and truncated frames are rejected. DACHENG two-motor uses the Sino inbound parser despite N-frame outbound. CB24 five-motor uses Dacheng's BCD alarm parser. The known Sino split is bounded to one current-session 23-byte report and expires after one second; consumed prefixes cannot contaminate later reports.

## Command Timing

A held action refreshes at the profile cadence. HA bounds normal taps by pulse count and supports timed and renewable holds through the scheduler. Release waits before each STOP submission: axis and union gestures release twice; presets, light and massage once. Special massage releases query state after the app's follow-up delay. Public STOP is one delayed submission; a cancelled active gesture owns its cleanup, so an existing release suppresses another STOP only for the same connection and covered side.

An expired or cancelled queued command sends no first movement. An admitted write settles within a bounded write timeout before release. Cleanup captures the original client, characteristic, layout and side; it never writes to a replacement connection. Concurrent independent motor streams are unavailable.
