# AI Bed

**Status:** Not yet tested on hardware. Limos and QRRM normal controls are supported; HJ001 and primary 305 offer a bounded subset. Other app layouts are unavailable.

**Credit:** Reverse engineering by [kristofferR](https://github.com/kristofferR/ha-adjustable-bed)

## Choosing a profile

Choose **AI Bed** and explicitly select the screen/route used in the app. A shared Bluetooth name or service supplies a candidate, never a reason to replace an existing receiver selection. Save the Bluetooth name for the app's M2/M3 and ESP feature gates.

### Aliases

These are separate app profiles. Matching wire encoders do not share timing, memory layouts or release policy.

## Wire codec

### Transports

The table above shows each route's service and characteristic. Ordinary writes use no response when that property exists. Reliable diagnostic/setup writes prefer response support; otherwise they wait 40 ms after transport completion. Reliable writes allow three attempts, a 2 s timeout and 120 ms after each exception. A successful write is not a firmware acknowledgement.

### Framing and checksum

Primary frames are `AA totalLength opcode parameters XOR`. The checksum is the XOR of preceding bytes. Limos uses the Limoss TEA codec with a fixed counter of 1; HJ001/QRRM use Richmat command framing.

Dynamic primary builders include waist `10,left,right`, constant heat `12,gear`, vibration `A1`, schedules `1E` and `20`, clock `04`, package query `41` and privacy PIN `9D`. Vibration strengths are 1–15, modes 0–2. Apply sends both strengths with preview flag 0. Preview sends flag 1, waits 60 ms, selects the mode, waits 60 ms and enables both channels. It ends with both off and restores the original strengths on its original connection. Preview requires a current strength report. Available preview durations are 3, 5, 10, 15 and 30 seconds.

Wake and inflation use Monday as bit 0. Enabled schedules require a selected day. Disabling wake writes hour/minute/week 0 and fixed trailer `14`. Disabling inflation preserves the freshly read hour/minute and clears weekdays. Mutation attempts invalidate checked schedule state before sending.

### Responses

BB status and QC fields remain raw diagnostics. Unknown or truncated fields do not become motor positions. The primary 2305 handler has no received checksum requirement; malformed lengths are dropped safely. A4 capability bits do not infer motor or memory counts, and a local one-second fallback does not establish hardware features. A8 assembles bounded indexed build-target strings. Clock replies record local receipt time only when a clock write is pending.

### STOP and release behavior

Primary motor holds emit first at 500 ms, refresh every 500 ms and finish with two `AA080800000000AA` writes. Cancel and task cancellation use fresh cleanup events and the captured original session. Reconnection never redirects release to another link.

Limos and HJ/QRRM stop by ending refresh. They never receive a fabricated release frame.

### Vectors

`tests/fixtures/ai_bed_vectors.json` and `tests/test_ai_bed_vectors.py` retain source-derived literal, formula, parser and state examples. Adaptive AES/CRC builders are reusable codec code; adaptive control workflows are unavailable.

## Primary profile

### Setup

Select the primary 305 subset explicitly. Optional FFE4 authentication is unavailable because its runtime string prefix is unresolved. Normal control writes do not assume authentication. Confirmed local auth replies can schedule the proved pairing-mode frame; that frame is not Android bonding.

### Controls

Use the app-labelled entities for movement and presets. The primary route has a native on/off light, head/foot/combined massage switches, a mode select, and a 10/20/30-minute timer select. Their displayed state is assumed from commands, not measured feedback. Constant heat and waist use number entities. Internal reports stay in protocol diagnostics.

Use `adjustable_bed.ai_bed` for inflation, vibration apply/preview, privacy PIN and settings queries. Preparation and execution share one child connection, including sequential pairs. Preview queries missing rollback strengths on that connection and requires a fresh reply before changing them. `set_alarm` writes wake schedules; `sync_clock` writes local MCU time.

### Positions and state

Raw motor, pressure and QC values have no invented physical scaling. Write-only controls retain unknown state until the bed reports it. Disconnection invalidates session state and permissions.

### Timing

Initial clock setup waits 1 s, queries status, waits 500 ms and writes local time. The primary heartbeat is every 15 s. Device-info and capability metadata remain independent of firmware acknowledgement.

### Limits

Advanced waist/foot heating helpers do not emit Bluetooth data and have no controls. Sleep Aid save settings, SleepTimer navigation, automatic QC verdicts/feedback, adaptive and sofa workflows, alternate entries and optional FFE4 authentication remain unavailable due to unresolved application behavior. No complete-app support is claimed. Wi-Fi provisioning, cloud/accounts, OTA and unrelated audio/companion services are outside this integration.
