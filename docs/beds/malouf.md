# Malouf/Lucid

**Status:** ✅ Tested on the NEW_OKIN and legacy FFE5 routes; the Malouf Base and Lucid Base app profiles are artifact-verified and need hardware testing

**Credit:** Reverse engineering by [kristofferR](https://github.com/kristofferR/ha-adjustable-bed)

One wire codec serves the Malouf and Lucid bases: the `malouf_new_okin` route and
the Malouf Base and Lucid Base app profiles (`malouf_app`). The apps reach five
GATT transports, each with its own frame. Three carry a 32-bit OKIN key word and
two carry a one-byte Richmat opcode. This guide covers the codec first, then one
section per profile. See
[Protocol codecs and app profiles](../design/protocol-codecs.md) for the
architecture. The [legacy FFE5 route](#legacy-ffe5-route) (`malouf_legacy_okin`)
sends the Keeson E6 frame and is described at the end.

## Known Models

- Malouf
- Lucid
- Structures

These are retail brands, not protocol identifiers. **Lucid L600 is not one
protocol.** Confirmed L600 devices include:

| Advertising/GATT evidence | Integration protocol | Packet format |
|---------------------------|----------------------|---------------|
| `Smartbed237...`, Nordic UART, OKIN manufacturer ID 89 / `DOT` payload | OKIN CB24 | 7 bytes |
| `OKIN-BLE...`, `BTCB` payload, connected FFE5/FFE9 | Malouf Legacy OKIN | 9 bytes |

The integration uses those BLE signals and connected services. It does not map
the string `L600` to either protocol.

The app profiles ship 16 model constructors; see [Models](#models).

### Framing and checksum

| Transport | Frame | Example: head up |
|-----------|-------|------------------|
| Richmat single | The opcode byte | `24` |
| Richmat framed | `6E 01 selector opcode sum8`, sum8 = `(0x6F + selector + opcode) & 0xFF` | `6E 01 00 24 93` |
| OKIN legacy | `E6 FE 16` + little-endian word + `00` + complement of the byte sum | `E6 FE 16 01 00 00 00 00 04` |
| OKIN custom | `04 02` + big-endian word + four zeros | `04 02 00 00 00 01 00 00 00 00` |
| OKIN new | `05 02` + big-endian word + two zeros | `05 02 00 00 00 01 00 00` |

The Richmat frames are built by the [Richmat codec](richmat.md) and the OKIN
legacy frame by the [Keeson codec](keeson.md) (its E6 frame with a side byte of
zero), which reproduce every literal byte for byte. The OKIN custom and new
frames open like an [Okin N-frame](okin-nframe.md) but carry more bytes than
their first byte counts, so they are this codec's own.

All writes use Android's numeric write type 2, `WRITE_TYPE_DEFAULT`, which is
acknowledged (`response=True`).

`repeats` always sets bit 0, plus bit 1 (Monday) through bit 7 (Sunday) for each
selected weekday; with no weekdays it sets only the next occurrence's day. The
new transport's `days` keeps bits 1-6 and moves Sunday to bit 0.

### Responses

Notification parsing preserves signed bytes and exact length/offset guards; it
does not infer angles or claim position feedback. Only the app profiles
subscribe.

| Transport | Accepted frames | Massage time | Light status |
|-----------|-----------------|--------------|--------------|
| OKIN legacy | Length 10, 16 or 20 only | Low nibble of byte 8 / 14 / 19; 1-3 means 10-30 minutes | Signed byte 7 / 13 / 18, shifted right by 6 |
| OKIN custom | Any | Signed byte 10 × 10 minutes | None |
| OKIN new | Byte 1 = `0x0B` | Signed byte 4: above 4 = 30, above 2 = 20, above 0 = 10 minutes | On when byte 9 or 13 is `1` |

### STOP and release behavior

The zero word (OKIN) or opcode `6E` (Richmat) releases every motor; the
[Transports](#transports) table spells each STOP frame. Every movement ends with
STOP sent under a fresh cancel event, so a cancelled command still releases the
motors. Memory saves end without STOP: the apps call a `stopCommand` name their
dispatcher does not recognize, so no frame is written. Preset STOP follows each
profile's [timing table](#timing-per-transport).

A [renewable hold](../SERVICES.md#renewable-holds) keeps refreshing the movement
frame at the same interval (the app's hold cadence for Malouf Base and Lucid
Base, the entry's pulse delay for `malouf_new_okin`) until the lease ends or a
STOP arrives, up to 30 s, then sends the same STOP. The Keeson-framed
`malouf_legacy_okin` route does the same with its zero frame.

### Vectors

`tests/malouf_vectors.py` freezes each profile's single frames: the app profiles
take every reachable literal of their accepted reports, and `malouf_new_okin`
every frame its pre-v5 controller sent. `tests/test_malouf_vectors.py` proves
each literal round-trips through the codec and that each profile sends exactly
its frozen frames.

## Profiles

### NEW_OKIN

**Status:** ✅ Tested

The `malouf_new_okin` bed type: OKIN new frames over Nordic UART.

#### Setup

Detection: the advertised service `01000001-0000-1000-8000-00805f9b34fb` selects
`malouf_new_okin`. Some newer Malouf S755 / DewertOkin `CB.24.42.28` bases
advertise only the Nordic UART service with a `Smartbed428...` name and OKIN
manufacturer payload starting `AB 01 02`; those are NEW_OKIN too, not the CB24
7-byte protocol. When the connected services show only the FFE5/FFE9 command
service, the entry is corrected to the [legacy FFE5 route](#legacy-ffe5-route).

Protocol and physical actuators are separate settings. Choose the layout that
matches the buttons on the physical remote:

- Back + legs (the confirmed two-motor L600 app profile)
- Back + legs + head tilt
- Back + legs + lumbar
- Back + legs + head tilt + lumbar
- Hi-Lo

Auto picks the layout from the motor count and never infers Hi-Lo. Memory
capacity is separate too: auto selects one slot for the two-motor layout and two
otherwise; both can be overridden in integration options.

Hi-Lo entries expose Back, Legs, Head End Tilt, Foot End Tilt and Bed Height.
`Bed Height` raises or lowers the whole frame by moving both lift columns
together; the two tilt controls move one column each.

#### Controls

Each control sends its word from the
[command table](#command-encoders) (column OKIN word (NEW_OKIN)). Lights are a
toggle; light on and off send the toggle too.

#### Timing

Movement repeats at the entry's motor pulse settings, then STOP; see
[Profile summary](#profile-summary) and [Timing per transport](#timing-per-transport).
A STOP that fails during cleanup is logged, not raised.

#### Evidence

Reverse engineered from Malouf Base 2.4.3 and checked against Lucid Base 1.3.3.
The route has no accepted report of its own; it sends only its frozen pre-v5
frames.

### Malouf Base / Lucid Base family

**Status:** ❓ Needs testing (artifact-verified, hardware unverified)

The `malouf_app` bed type. Retail model, GATT transport and physical role are
independent choices. Controls follow the selected model and its reachable app
routes; a model label alone never enables a command that has no endpoint in the
selected app and transport.

#### Setup

Select **Malouf Base / Lucid Base app** under Malouf/Lucid, then choose the
Android app and exact model used with your bed. Detection: none, this is an
explicit choice.

- Setup offers the app's packaged model picker (see [Models](#models)). Some
  models are only reachable through the apps' persisted model selection; options
  keep an existing persisted-only model for that same app. Changing apps
  refreshes the model choices before saving.
- Choose the physical primary/secondary role used in the app. Home Assistant's
  Left/Right names do not prove that role.
- Automatic transport selection uses the observed Bluetooth name (`X1RM` or
  `QRRM` for Richmat, `OKIN` or `Smartbed` for OKIN; no name means OKIN) and the
  connected GATT services. It rejects ambiguous or incomplete layouts. An
  explicit transport must still match a complete writable layout.
- Shared UART and custom service identifiers never select an app or retail model.
- When combining two Bluetooth addresses, configure each bed separately before
  combining them. Single-address pairing is not offered: the app's secondary
  selector covers only some commands, while STOP and other actions stay global.

#### Controls

Each control sends its value from the [command table](#command-encoders). The
connected transport removes routes it has no endpoint for:

- Good Life combined movement has no OKIN endpoint and is suppressed there.
- Altitude head tilt and full tilt are Richmat-only.
- Richmat massage timers are direct 10/20/30-minute controls where reachable.
  OKIN has a timer-step command rather than a direct duration. Massage off is
  Richmat-only.
- Framed Richmat sends selector 1 on a secondary bed only for the actions listed
  under the command table; every other action, STOP included, uses selector 0.
- The light toggle is native. For a feedback light whose state is still unknown,
  use the card's light toggle or Home Assistant's `light.toggle`; explicit
  `light.turn_on` and `light.turn_off` need known feedback.

##### Two-address split-head routing

Home Assistant selects physical targets explicitly, rather than importing the
apps' persisted `ActiveBed` selection and `motorSwapped` UI state. Configure each
physical bed's app/model/primary role first. Use the child device IDs as the main
and partner targets. The apps do not establish synchronized physical motion.

For a supported main **Both/Dual** control and an inactive partner's **Legs**,
use this parallel action sequence. The existing simultaneous-movement action
works with any controller that declares that capability, despite its historic
`linak_` name. Replace the two device-ID placeholders with your child IDs.

```yaml
parallel:
  - action: adjustable_bed.linak_move_simultaneously
    data:
      device_id: YOUR_MAIN_DEVICE_ID
      first_motor: back
      first_direction: up
      second_motor: legs
      second_direction: up
      duration_ms: 1000
  - action: adjustable_bed.timed_move
    data:
      device_id: YOUR_PARTNER_DEVICE_ID
      motor: legs
      direction: up
      duration_ms: 1000
```

Choose `down` for both direction fields to lower them. Each operation retains
its own physical command lock and cancellation-safe STOP. The main receives its
combined command, while the partner receives foot movement, rather than sending
the main's combined command to both beds.

| App operation | Explicit Home Assistant targets |
|---------------|----------------------------------|
| Selected-side head movement | `timed_move`, motor `back`, main child only |
| Foot movement shared with inactive partner | `timed_move`, motor `legs`, both child IDs |
| Both/Dual movement with partner foot | Parallel sequence above |
| STOP/release | `stop_all`, both child IDs or paired parent |
| Position preset | Press the corresponding preset buttons on both children; memory recall can use `goto_preset` on the paired parent |
| Save memory | `save_preset` on the selected child only; Lucid Good Life uses its **Save Memory 2** button on that child |
| Partner foot massage | Press the foot-massage action on both children |

Malouf's Good Life **All** has no inactive partner remap, so run only the main
combined action; Lucid's differs (see [Lucid Base](#lucid-base)). Shared app UI
light state and side-selection persistence are application behavior, not
inferred controller feedback or a physical-side proof.

#### Timing

Movement sends at once and refreshes while held, then STOP after the release
delay; see [Profile summary](#profile-summary). Presets, memory saves, clock and
alarm writes and the `00 B0` status query after light and massage actions follow
each transport's row in [Timing per transport](#timing-per-transport). A memory
save on a device named `smartbed238` uses the special slot 1 word. Richmat
memory programming sends its save opcode once.

#### Notifications

OKIN transports subscribe to their notify characteristic and use the
[Responses](#responses) parser. Light state feedback is used on OKIN legacy and
OKIN new; any nonzero status means on. OKIN massage models add a
massage-remaining sensor in minutes.

#### Services

Use `adjustable_bed.malouf_set_alarm` to set or clear an alarm. The selected
model must expose the app's alarm UI, and the connected transport must be OKIN.
The choices are the alarm types above, subject to the model's memory capacity.
An alarm choice can be available even when the same manual preset is absent.

- Time uses Home Assistant's configured local time zone and minute precision.
- Selected weekdays create a repeating alarm. An empty weekday list selects the
  next occurrence of that local time, using the app's one-shot weekday encoding.
- Clock synchronization runs immediately before programming an enabled alarm.
  `adjustable_bed.sync_clock` (or the older `malouf_sync_clock`) also permits
  explicit clock synchronization. Connecting alone never writes the clock.
- Both actions validate every selected physical bed before any write and use
  the coordinator's serialized configuration path. An active movement is not
  cancelled to change an alarm.

See [action examples](../SERVICES.md#malouf-base--lucid-base-clock-and-alarm).

  an OKIN main it has no main write endpoint even though the app can move the
  inactive partner's foot; that partial combined route is excluded for safety.
  Standalone head and foot control remain available.

### Legacy FFE5 route

**Status:** ✅ Tested

The `malouf_legacy_okin` bed type sends the Keeson E6 frame
(`E6 FE 16 01 00 00 00 00 04` is head up) to write characteristic
`0000ffe9-0000-1000-8000-00805f9b34fb` in service
`0000ffe5-0000-1000-8000-00805f9b34fb`. It uses the OKIN words of the
[command table](#command-encoders) (column OKIN word (NEW_OKIN)) and the same
layout and memory settings as [NEW_OKIN](#new_okin). Its profile is
`malouf_legacy_okin` in the Keeson guide's
[controller profiles](keeson.md#controller-profiles); the controller builds the
frame through that codec.

Some Lucid L600 / DewertOKIN `OKIN-BLE` controllers advertise the Malouf/Lucid
family UUID (`01000001-...`) but expose only the FFE5/FFE9 command service after
connection. Their advertising manufacturer payload commonly contains `BTCB`.
Those devices are treated as this route.

| Operation | Timing |
|-----------|--------|
| Held motor command | Motor pulse settings, then STOP |
| Preset recall | 3 queued acknowledged writes, no STOP |
| Save memory | 85 writes at 150 ms after one interval, no STOP |
