### Framing and checksum

The control prefix declares five despite carrying six payload octets. The final
octet is the save/release flag. Triple alarms likewise retain their source's
declared length rather than being normalized. No checksum, sequence,
authentication or side selector is added.

### Responses

BED status publishes privacy, detection, anti-snore enabled/level, massage timer,
pattern and strength indices. These are reported raw option indices, not motor
positions or remaining minutes. Complete alarm replies publish the stored fields;
the empty enabled alarm is normalized to disabled. Configuration selects triple
alarms only when the explicit alarm-count field reports three. Truncated replies
are rejected, and separate sensing/history notifications never become BED state.

### STOP and release behavior

Every held action ends with its captured zero or save release on the same
connection. Cancellation drains cleanup using a fresh event. Home Assistant
bounds movement by elapsed time, rejects stale callbacks and writes after session
replacement, and never catches up missed refreshes. The app's mutable delayed
STOP and missing disposal cleanup are not safety guarantees.

### Vectors

Frozen command, parameter, receive and corrected alarm cases live in
`tests/fixtures/onlysnore/`; `tests/test_onlysnore_vectors.py` calls production code.
The distinct control and receive formats require their own minimal codec,
reusing the shared parameter-record encoder. Existing N-frame and Smart Sleep
carriers do not reproduce this app's complete literals.

## Profiles

### Snore Monitor BED profile

**App:** [Snore Monitor](https://play.google.com/store/apps/details?id=com.okin.sleepMonitor.onlySnore) 2.3.8, `com.okin.sleepMonitor.onlySnore`

**Status:** ❓ Hardware unverified

#### Setup

Choose **Snore Monitor** in manual setup and select the app's model label.
Discovery requires the app's case-insensitive `SLEEP_V` prefix, manufacturer
company 89, and the reversed manufacturer identity matching the selected address.
The model getter reads original byte six; the scanner's double-only fast path
does not change the other labels. Wi-Fi selection is excluded. Configure and
restored entries retain the per-physical-bed model. Two-address pairs keep each
side's settings; there is no single-address side selector.

#### Movement and presets

Use the covers or dashboard holds for app-labelled actuators. The Flat, Reading,
TV, Zero Gravity and Anti-Snore preset buttons recall with a finite hold, and the
save buttons save only the selected non-flat preset. Holding a programmable preset
through the source threshold changes to its save frame. Renewable holds use Home Assistant's admitted lease; sequential paired
Both holds are refused before motion.

#### Massage and lights

The **Massage** switch starts and stops massage; it is on while the reported
massage timer option is nonzero. Use the cycle buttons for wave (Massage: Mode),
timer and head/foot strength. The reported option indices stay internal. No
absolute massage level setter, light brightness, color or discrete light state is
inferred.

#### Settings and alarms

Use the **Privacy** and **Snore detection** switches and the **Anti-snore
intervention** select. The **Test anti-snore level** buttons run a bounded
demonstration and send the distinct intervention stop at completion or
cancellation. **Refresh status** (diagnostic, disabled by default) re-queries
status and alarms; HA also queries them on every connection.

Each alarm slot shows an **Alarm N time** sensor, with the repeat mask, action
code and soft wake as attributes, and an **Alarm N enabled** binary sensor.
**Firmware version** and **Hardware version** are diagnostic and disabled by
default. The app's local management command (`management_1`) has no known
user-visible effect and is not exposed.
These names describe device commands and make no clinical efficacy claim.

`adjustable_bed.onlysnore_set_alarm` takes the one-based slot, enabled state,
minute-precision time, exact app week mask, action index and triple-only soft wake.
All selected beds are validated before execution. For one-time masks, single
alarms retain current seconds, clear subseconds, advance by an elapsed day when
strictly earlier, and mutate their model mask. Triple alarms zero seconds, use a
separate weekday clock, and retain the model mask. Their Sunday rollover may
produce a local mask that truncates to zero on the wire. These source quirks are
preserved rather than normalized into a different schedule.

## Notes

Separate sleep sensing/reporting, audio, cloud/accounts, networking, OTA and
phone-only preferences are outside this BED integration. Home Assistant handles
adapter/proxy setup and notification subscription. Its Bluetooth backend negotiates
MTU; these BED commands fit the default ATT payload. No mandatory bonding is added.
