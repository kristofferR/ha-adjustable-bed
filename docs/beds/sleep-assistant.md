## Known Models

The original Sleep Assist app lists names starting with case-sensitive `KSBT`
and containing exactly thirteen characters. A name identifies a Bluetooth
candidate, not its model or optional features. There is no built-in product catalog.

The app requests MTU 247 and subscribes before control. Home Assistant manages
adapter/proxy MTU negotiation. All normal commands fit within twenty bytes,
except longer ASCII configuration records, which require the available link's
write support. The app never selects Android's write type explicitly. The
integration uses write-with-response when the discovered characteristic offers
it, otherwise its write-without-response property; this is not a claim about
a hardware default. No BLE PIN, bond or crypto handshake is required.

### Framing and checksum

Controls are fourteen binary bytes with the little-endian key in bytes 7–10,
a complement of bytes 5–10, and the fixed F3/55 ending. Only the codec's explicit
instruction values are encoded; an unlisted combined key becomes neutral.
The RGB frame has separate inner and outer complement sums.

Settings are uppercase ASCII hexadecimal text sent unchanged, without a terminator.
They must not be hex-decoded before writing. Most complement the decoded body sum;
identity and anti-snore have their own checksum rules. Sensor gain overwrites both
port values, including when a side argument is supplied. Calibration time fields
are little-endian 16-bit values; their physical units are unknown.

RGB channel changes invert each selected channel and multiply by the selected
1.0, 0.6 or 0.2 brightness using Java float arithmetic. Brightness starts at the app’s high setting. A brightness-only change requires
a color selected on the current connection, so it cannot overwrite an unknown
color after reconnect.

### Responses

Notifications are binary. DD/EE markers can split frames within a callback; there
is no cross-callback assembly or general checksum validation. A nineteen-byte
first-DD callback reads light state from signed byte 14; a twenty-two-byte one
reads byte 15. These writers are independent of the brightness reply and version
gate. Signed values 80–FF shift negative and mean off, not an unsigned bit.
Brightness is a separate diagnostic observation, not a replacement light state.

Timer offsets differ across nineteen, twenty-two, thirty-two and thirty-three-byte
forms. Values FF/1/2/3 map to off/10/20/30 minutes. Additional massage status expires
after 2.5 seconds for MCU above 2.09, otherwise 5.5 seconds; one-button status expires
after 3.5 seconds. These are display indicators, not movement durations.

8B supplies BT/MCU/DSP versions and a bed-mode field, never motor count. 95/11
supplies DSP text. 8D supplies gain/out-of-bed calibration, 90 local storage, 83
sequential alarm rows and 84 anti-snore settings. 88/8E request clock synchronization;
8E results in two writes spaced 100 ms apart. Physiological 8A notifications contain
side and occupancy fields; breathing/movement offsets change at BT 3.0. Absent or
negative rate values are unknown. Physiological sides do not address motor commands.

### STOP and release behavior

Motors stream immediately at 200 ms and release with the zero instruction after
800 ms. Named preset holds use the same cadence and neutrals after 800/1300 ms.
Tap commands wait 400 ms, with neutrals scheduled 1300/1500/1700 ms from invocation;
named preset taps first classify for 200 ms. Flat sends immediately. The toolbar
light path sends immediately with neutrals after 400/600/800/1000 ms.

Home Assistant cancels pending taps and streams and finishes cleanup before handing
the command lane to another operation. It does not reproduce the app's CANCEL
behavior that can leave a timer or delayed preset running. A retired BLE session
cannot send release to a replacement connection. No extra STOP opcode is invented.

## Profiles

### Sleep Assist profile

#### Detection / Setup

Choose additional controls and presets only when they exist for the selected bed.
Preset order matters. All four anti-snore/Memory/Relax/TV tokens select the four-slot
group; otherwise at least one selects the three-slot group. One-button sleep changes
only the first horizontal slot's visibility at MCU 2.05 and BT 2.18 or newer. Other
supplied slots can remain visible without that gate. Its dispatch has no global
version condition. No concrete server model assignment is inferred from this rule.

The optional device identity is eight decimal digits from the selected device.
It is independent of the BLE advertisement and never supplies a model name.
Under Advanced, selected model settings accept only:

- `calibration`: four integers, lift time/speed and down time/speed.
- `gain`: one byte applied to both sensor ports.
- `out_of_bed`: two sixteen-character hexadecimal calibration strings.
- `anti_snore`: five integers, initial level/intensity/package/period/movement.
- `anti_snore_levels`: optional additional five-integer sets, one per known level.
  The sensitivity select offers Off plus only the levels with supplied parameters.

Use values from the selected model's existing configuration. Leave unknown settings
empty. No account connection, login, model query or guessed calibration is needed.
Reconfigure changes these local selections; settings belong to each physical bed.

#### Controls and behavior

Head/feet movement and flat/Zero Gravity remain available without optional metadata.
Tilt/lumbar require their own selected controls. Head/feet increase/decrease requires
both corresponding controls; otherwise individual head/feet cycles follow the
selected cycle controls. Combined massage also requires the timer control.

Ordinary lights use notification state to avoid blind toggle-based on/off commands.
The Sleep8 palette selects off or one of six colors. The 4193 light supports RGB and
three brightness steps. Unknown light state requires fresh feedback before on/off.
Alarms use Monday-based Home Assistant weekdays mapped to the app's Sunday bit.
Automatic flat offers 20–120 minutes in 20-minute steps; zero clears slot 6.

#### Commands

See the generated codec tables above. The shared `set_alarm` and `sync_clock`
actions use this profile's exact encoders.

#### Position feedback / Notifications

There are no position sliders. Live physiological state is kept per sensor side,
and measurements clear on reconnect. Preset buttons the bed reported before remain
callable offline, while commands recheck current firmware before movement.
Raw calibration/version fields stay in
diagnostics rather than becoming dashboard entities.

#### Command timing

The profile supports standalone entries; Combine Beds and one-address side
controls are unavailable. Anti-snore offers Off and only the level whose
parameters were supplied. A successful choice survives reconnects within the
Home Assistant session and supersedes a pending startup write.

After notification setup, supplied identity/configuration and status queries use
the current connection only. Supplied anti-snore settings are applied two seconds
after version feedback and the fixed 6/21-hour interval after three seconds.
The neutral status refresh runs at 500/800/1000/1300 ms on its owning link.
Alarm rows are spaced 200 ms. Automatic flat is one-shot; both alarm paths
refresh its row and invalidate an unknown original countdown duration. Write
failures use bounded native retries.
