### Packet Format

Control frames carry a fixed prefix, a little-endian key and the sum of every
preceding byte modulo 256. The address response uses a separate prefix and the
initiating Bluetooth adapter's six address octets. There is no encryption,
sequence counter or side field.

### Write Mode

The app leaves ATT write mode to the discovered characteristic. Home Assistant
uses Android's default: without response whenever that property is present,
otherwise with response. Both the write and notify characteristics must belong
to the declared service. No PIN or bonding step is defined.

The response identifies the adapter initiating the connection, never the bed.
Local host adapters and ESPHome proxies that report their Bluetooth address can
provide it. An unknown adapter identity, including a proxy exposing only its
Wi-Fi address, leaves recognition pending and sends no substituted identity.
Controls remain available because the app gates them on the BLE link rather
than recognition. Recognition here means a completed address-response write,
not authentication or device acknowledgement.

Notifications are handled per message, without reassembly. Truncated indicators
are safely ignored. Their unknown physical meaning produces no sensor, light
state or inferred position. Disconnect clears the indicator and recognition.

### AMINACH Platinum

**App:** AMINACH Platinum 1.36, `com.moteck.AMBA2`

**Status:** Not yet tested

#### Setup

Choose **AMINACH Platinum**, then the number of motors. The case-sensitive name
prefix in the profile table suggests this app. Unnamed receivers can be added
by Bluetooth address after explicitly selecting the app. The shared UART
service alone does not identify a Platinum receiver.

#### Controls

The app's BACK controls become Back, FOOT becomes Legs, and the separate HEAD
becomes Head. Sleep, Light and Memo keep their button meanings. They do not
create a Flat action, memory slots or an assumed light state. Use the shared
`hold_control` action or the dashboard card to hold a key.

#### Timing

Each gesture writes immediately and repeats at the interval in the profile
table. Memo starts a new gesture with its own shorter interval and delays a
quick ordinary release until its minimum elapsed time. A reused Android worker
resets to the normal interval; Home Assistant owns a new worker for each gesture.
No distinct long-press command is defined. User-controlled holds retain any
firmware-dependent interpretation of the held key.

Every gesture sends the common release after completion or cancellation. STOP
also sends this release. Writes and cleanup are serialized and tied to the
original link, so a delayed release cannot reach a replacement connection.
A quick card release of Memo keeps refreshing until its minimum elapsed time.
Explicit STOP, command replacement, cancellation and lease expiry preempt those
refreshes and release at once. Unlike the app's unjoined workers, Home Assistant
settles cleanup before the next command.

#### Evidence

Based on AMINACH Platinum 1.36. Physical directions, button effects, release
behavior and connection recognition need confirmation from users after a beta
or release.
