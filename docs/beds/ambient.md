# M3 Ambient

**Status:** Not yet tested on hardware

**Credit:** Reverse engineering by [kristofferR](https://github.com/kristofferR/ha-adjustable-bed)

## Known Models

- M3 Ambient one-piece and split layouts.
- The app looks for Bluetooth names containing `CONTROL_BOX`. Other devices can use that name.

## Features

| Feature | Supported |
|---------|-----------|
| Position targets | Head, feet and neck on a raw scale, with separately labeled left and right controls on a split bed |
| Position feedback | Raw values from bed notifications |
| Presets | Flat position, TV, Zero Gravity and Anti-snore. One-piece beds also have Home flat. |
| Memory presets | Unavailable |
| Massage | Independent shoulder and feet levels from off through level 3 |
| Lights | On, off and RGB |
| Ventilation | Independent left and right fan levels |
| Heat | Three zones per side and an optional two-hour timer |
| Diagnostics | Power supply and control-box firmware |

### Packet Format

P1 short commands use the HHC binary encoder with a four-byte body and XOR.
The one-piece and split position targets use distinct headers and a fixed
five-byte tail. One-piece targets keep the reserved fields from the current
link's strict target-shaped report when available. Split targets carry selector
`AA` for left or `BB` for right on the same connection.

P2 uses the `51 9F` header and an additive low-byte checksum. Heat encodes the
right shoulder, torso and legs, followed by the left shoulder, torso and legs.

### Write Mode

The controller subscribes to the notification role before admitting application
writes. Every command uses an ATT write with response on the resolved write
characteristic.

## Detection / Setup

Choose **M3 Ambient app**, then select **One-piece** or **Split** to match the
bed. Both layouts use one Home Assistant device and one Bluetooth connection.
Split positions have an explicit side on each control. Light and massage are
shared controls. Fan and heat have their own left and right channels.

### Memory

The integration exposes the app's coordinate presets as buttons. For a custom
preset, save the three coordinates in a Home Assistant script and send them
with the [position action](../SERVICES.md#ambient_set_position).

### Actions

The [M3 Ambient actions](../SERVICES.md#m3-ambient) send all three positions,
set three heat zones on one side or set raw RGB without a power command. The
regular light picker scales each Home Assistant RGB channel to the app's
0–120 range. The raw RGB action accepts full channel bytes.

## Position Feedback / Notifications

The controller accepts strict P1 position and combined-state reports. An
individual position slider waits for a new report for its selected side before
copying the other two axes. The complete-position action sends a single target
with the three supplied values.

Combined P1 state supplies positions, massage and RGB. Individual massage and
power echoes must match their complete frames. P2 supplies fan levels, supply
type, six heat bytes and firmware. A successful write alone does not update the
reported state.

| Optional heat timer | 3 s after a matching report |

The **Refresh bed state** button repeats the read-only startup queries. Every
heat change first reads all six current levels and keeps the untouched zones
from that response. After a heat write, only a new checksum-valid report
matching all six bytes confirms the change. A request with a two-hour timer
sends it only after confirmation, on the same connection. Each position
command is a single target. There is no protocol STOP or held refresh.

## Notes

The raw position values have no assigned physical unit. A split bed's physical
feet and lumbar behavior, combined-state trailing bytes, and on-device
readbacks still need hardware validation. Active lumbar control and the older
demo routes are unavailable.
