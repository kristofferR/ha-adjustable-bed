### Framing and checksum

The native custom plaintext contains a command header, payload length, LDP payload,
embedded repeat count, delay byte and a literal zero. It is zero-padded to a multiple
of four, encrypted as little-endian XXTEA words with fixed protocol constants, then
protected by CRC-CCITT (initial 0xffff, polynomial 0x1021) over ciphertext. The CRC is
little-endian and precedes ciphertext. Two length-minus-four bytes precede the CRC.
SLIP adds C0 delimiters and escapes C0 and DB. The length headers are outside CRC
coverage; invalid lengths are rejected safely.

These constants are part of the protocol. No account credential, PIN or session key
is entered. The app requests Android bonding, which does not establish that every
receiver requires pairing. Home Assistant handles actual security errors through
its shared Bluetooth pairing workflow.

### Responses

Notifications use the same SLIP, length, CRC and XXTEA pipeline, retaining split
frames and escapes across notifications. Custom acknowledgement ID 3 ends the
response wait. Its status is not reliable hardware confirmation. Other SDK response
IDs do not supply live position, light, massage or capability state to this app.

### STOP and release behavior

Normal movement cleanup sends key release with embedded count 3/delay 30. This is
the app's touch-UP command. Home Assistant also uses that release when a
held operation is cancelled. An accepted frame finishes all its fragments before
cleanup, to its original client only. No release is sent to a replacement session.
The Android app omits release on several cancellation and radio-loss paths, so
stopping after loss of the radio link remains unverified.

## Profiles

### Android

#### Detection / Setup

Manufacturer ID 1351 is checked without a name prefix or advertised-service filter.
A seven-byte record is accepted. An eleven-byte record needs LL, NS or FS at offsets
7–8 and byte 9 equal to zero. The app also accepts byte 9 equal to one when already
bonded; automatic discovery does not assume that bond. Manual selection remains
available. When several manufacturer records exist, the lowest company ID is the
app's first record.

| Field | Values | Default |
|-------|--------|---------|
| Product type | Queen, King, Twin XL | Queen |
| Has massage | Enabled / disabled | Enabled |

All six size/massage combinations keep two command groups. Massage controls are
absent when disabled. No model query, cascade control or single-address side selector
is exposed. Two separate receivers keep their settings independently.

#### Controls

Back and legs use the shared motor controls. Flat and memories send any-key before
recall, with a 50 ms enqueue gap in the app. The integration serializes the frames
and preserves that minimum gap. Memory programming uses the shared confirmed-save
controls, without a held save gesture.

Massage Form Two sends wire program 2, while Form Three sends wire program 1. These
names follow the visible controls. Intensity is relative, without an absolute level
or zone claim. The local timer offers 1–40 minutes, initially 10, and sends off when
it expires while connected. The active countdown retains its BLE link and restores
the configured handoff after expiry or off. An expired timer retries off before the next movement;
with 1–30 seconds left, movement first sends off and waits 500 ms. It is not a timer
packet. Toggle and explicit-off are the only light controls.

Flat realignment and factory reset require confirmation and start disabled. Each
confirmation sends only its reset frame. The app then presents a separate held
feet-down control; use the existing legs-down hold when ready to perform that
followup. Reset does not start movement automatically or transfer firmware.

subscription enables notifications through Home Assistant's Bluetooth stack.

## Notes

Target codes in the five height presets are neither measured angles nor
percentages, so they do not create position sliders. No clock or alarm capability
is exposed. Physical motor/preset mapping, encoded device timing and termination
after radio loss remain unverified.
