# Langjue Comfort Smart Bed

**Status:** Not yet tested (offline protocol and Home Assistant tests)

**Credit:** Reverse engineering by [kristofferR](https://github.com/kristofferR/ha-adjustable-bed)

## Known Models

- Beds controlled by Comfort Smart Bed over the P1 Bluetooth service. The app's list of retail models and layouts is unavailable.

## Features

| Feature | Supported |
|---------|-----------|
| Motor control | Back and legs after you confirm the app shows Head then Foot and the bed reports two motors |
| Position feedback | No angle or position reports |
| Position presets | Flat, Relax to Sleep, Zero G, Reading, Anti-Snoring, Stretch, Backrest |
| Memory presets | Three recall and save slots |
| Massage | Optional head and foot levels, four patterns, timer, start and off |
| Lights | Optional under-bed light with on, off and reported state |
| Bed clock and alarm | Clock sync, one-time or weekly alarm, enable or disable the stored alarm |

### Packet Format

The header contains the marker, the low byte of the payload sum, the quick
motion vector length or zero, a reserved zero, the opcode and its argument.
The payload follows the header. The argument is an operation-specific field.

### Write Mode

The write characteristic must support both Write and Write Without Response.
The notification characteristic must support Notify and must not be a Write
candidate. The controller requires exactly one characteristic for each role
inside the P1 service and uses the discovered characteristic objects.

## Detection / Setup

Choose **Comfort Smart Bed app (Langjue)** manually for the Bluetooth device
that the app uses as its bed. The app's `Smart` name filter also matches
unrelated devices, so Home Assistant uses the saved device selection and
verifies the connected GATT service. No protocol-specific PIN is required.

Choose **Presets and STOP** when the app's motor order is unknown. Select
**Two motors, confirmed Head then Foot in the app** only when the app shows
those two motor controls in that order. A live report of any other motor count
blocks directional writes. Enable light and massage controls only if the app
shows under-bed lighting and both massage zones, respectively. A live device
with missing or ambiguous P1 roles returns setup to device selection.
Reconfigure to this profile requires a successful live receiver check.

Combined controls require two ready Langjue receivers connected at the same
time. Each must report a usable motor count and match any confirmed
two-motor layout. A separate side can still be controlled on its own.

Use `adjustable_bed.sync_clock` to set the bed clock from Home Assistant's
local time. Use `adjustable_bed.set_alarm` to program the bed alarm. The
`wake_action` field is required when programming an enabled alarm. An empty
weekday list selects a one-time alarm. The **Bed alarm** switch reads the
current record before changing its enabled flag. Its reported state remains
unknown until an alarm action reads the bed's record. If the pair uses one
Bluetooth connection at a time, set the alarm on each side in a separate
action so its check and write use the same connection. An alarm action claims
its selected receivers until it finishes. A second alarm action can run at the
same time on other receivers.

## Position Feedback / Notifications

The handshake reply reports motor count as a decimal value written in the
byte's hexadecimal digits. A valid count that fits the connected BLE write
size is required for preset movement, directional movement and STOP. This
allows STOP to use the same vector width as the bed. Light replies report
on or off. A massage level reply updates only the zone it names. A separate
massage time reply also uses decimal digits. The raw massage status code is
available in the diagnostics download. The alarm reply carries the stored record.

|---|---|---|
| Handshake | `55 8d 00 00 81 08 00 02 00 00 7e fa 1c f7` | With response |

| Read release date | `55 00 00 00 83 00` | With response |
| Read light state | `55 00 00 00 18 08` | With response |
<!-- /generated -->

On connection, the controller enables notifications, then sends the handshake.
The version, release-date and light queries advance in response to the previous
reply. A missing reply ends that sequence.

Directional movement is serialized. Releasing the control, cancelling a move
or reaching its time limit ends the refreshes and attempts one all-neutral STOP
on the same connection. A completed preset tap sends a single frame. Physical
STOP delivery and firmware behavior after a link loss remain unverified.

## Notes

The P1 Anti-Snoring position preset moves the bed directly. Automatic anti-snore
settings, sleep reports and firmware updates belong to the separate sleep
accessory.
