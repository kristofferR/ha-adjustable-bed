# Sleep Assist Pro

**Status:** Not yet tested on hardware

**Credit:** Reverse engineering by [kristofferR](https://github.com/kristofferR/ha-adjustable-bed)

## Known Models

The app selects its Bluetooth protocol from the saved device ID. Receivers can
use names starting with Base-i4, Base-i5, KSBT, KSWF, KSPSBED or KSSLBED. Other
apps also use some of these prefixes.

## Features

| Feature | Supported |
|---------|-----------|
| Motor control | Head, foot, head tilt, a second head or lumbar, according to the selected remote |
| Presets | Flat, zero gravity, anti-snore, music, relax/read, TV and demonstration, when selected |
| Massage | The selected all-zone, timer or individual zone buttons |
| Under-bed light | Toggle on all routes. P1–P3 can report on/off state and provide optional RGB. P3 supports the ErgoSportive dimmer. |
| Motor position feedback | — |
| Memory programming and bed alarms | — |

P1 uses the Keeson E6 little-endian carrier with side byte zero. P2 uses the
six-byte `04 02` carrier and a separate status query. P3 uses a checked binary
AA key. P4 uses compact JSON with an eight-digit key and mode fields. P5 uses
compact JSON with an uppercase hex inner frame, the saved ID and epoch seconds.
P4 and P5 send successive chunks of up to 20 bytes.

Home Assistant selects the first matching GATT service on P1 and P2 and
requires the selected tuple's write and receive characteristics. It uses a
write with response when the characteristic advertises it, or a write without
response when that is what the bed advertises.

## Detection / Setup

Choose **Sleep Assist Pro**, then enter the Bluetooth ID saved in the app,
preserving its spelling. Discovery can suggest the app and fill the ID. Use
the app's ID if it differs from the advertised name.

| Route | Saved ID rule |
|-------|---------------|
| P1 | Starts with Base-i4 or Base-i5 |
| P2 | Starts with KSBT and is 16 UTF-16 code units long |
| P3 | Starts with KSBT and is 13 UTF-16 code units long |
| P4 | Starts with KSWF and is 16 UTF-16 code units long |
| P5 | Starts with KSPSBED or KSSLBED |

The route match ignores case. The JSON routes accept IDs made of ASCII letters,
digits, periods, underscores and hyphens. Select the controls displayed for your
bed in the app. Leave controls you do not see unselected. Enable under-bed
lighting separately. Enter the app's product name when selecting the
ErgoSportive dimmer or the DawnHouse controls. The DawnHouse choice is
available on P4 and P5. P5 exposes Bed in and Bed out. P4 also exposes Bed up
and Bed down.

Set up each receiver as a standalone entry. A double-head receiver can expose
both head actuators through one connection.

## Position Feedback / Notifications

On P1–P3, the selected notification channel can provide lamp and massage timer
updates. Compatible P3 firmware can also report the massage countdown.
Lamp state starts unknown on each connection. Change RGB or the
ErgoSportive dimmer once the bed reports that the lamp is on. Choose an RGB
color on each connection before changing the RGB brightness preset. RGB
brightness has 20%, 60% and 100% steps. P4 and P5 indications carry no decoded
remote state here. Their light control is a toggle button.

## Command Timing

Held movement refreshes every 200 ms. The controller ends refresh on release
or cancellation and finishes any in-flight split packet. P1, P3 and P4 have a
neutral movement follow-up. P2 follows with a status request. P5 ends refresh
without a follow-up frame. Held named presets have their own release schedule.
The physical effects of release are awaiting hardware confirmation.

Home Assistant keeps a subscription for the current BLE connection. It makes a
status request when enabled controls need P1–P3 feedback. The P3 clock can be
set through the integration's clock sync action.
