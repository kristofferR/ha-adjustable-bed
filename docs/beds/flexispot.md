Writes use the discovered characteristic's write-with-response property when
available, otherwise write-without-response. Both roles must belong to the listed
service. Notifications are required; there is no startup query. GhostBed synchronizes the bed clock after subscription succeeds.

### Framing and checksum

Every record has 20 bytes: header `9B`, selected alarm slot at offset 1, opcode
at 2, key at 3, optional payload at 4–16, CRC16 low/high at 17–18, footer `9D`.
CRC16 starts at `FFFF`, uses reflected polynomial `A001`, and covers only 2–16.
The selected alarm slot is outside the CRC. There is no encryption or fragmentation.

### Responses

The parser accepts only complete records with the header/footer above. It does
not validate incoming CRC, reassemble fragments or treat notifications as ACKs.
Type `04` reports light state. Types `26` and `27` report light, massage levels,
pattern and time, both alarms, and snore configuration. These values never
represent actuator positions. Signed byte division/remainder follows the app.
Unknown and invalid values remain unknown; raw fields stay in diagnostics.

### STOP and release behavior

Held motor commands refresh until release or the bounded HA duration ends.
Only after submitting a motion frame does HA wait for the write to settle, then
send that motor's release on its original connection. Cancellation or expiry
before submission sends nothing. A replaced connection receives no old release.
Explicit Stop sends the proven per-motor frames; Stop all fans them out.
Presets are single writes without an invented release or renewable hold.

## Profiles

### Flexispot 1.1

**App:** [Flexispot](https://play.google.com/store/apps/details?id=com.loctek.flexispotpro) 1.1 (2), `com.loctek.flexispotpro`

**Status:** Not yet tested

#### Setup

The shared name filter suggests the app, then setup requires a model. Configure
or Reconfigure preserves that choice per receiver. The model determines motors,
massage and light controls. There are no position sliders or angle sensors.

#### Controls

The generated tables list each model's commands. Programming uses the card's Set
mode or a confirmed save button. Restore original settings also asks for
confirmation; the receiver's exact reset scope and persistence are unknown.

Massage power shows the last successfully delivered command, not measured power.
EB803 intensity changes send relative steps from a valid current-link report.
After any delivered step the affected level is unknown until another report,
including when its caller is cancelled while the write is in flight. Older models
have increase/decrease buttons. The timer sends the selected minute value; incoming
time displays as time plus one, matching the app. Zero is a timer value, not a
proven massage-off command. Use the separate massage power switch to turn it off.

EB803 snore controls require valid current-link settings to preserve the other
side. The angle setting uses the other side's sensitivity in its packed pair,
as this version of the app does. Global enable/disable sends zero angle and
sensitivity pairs. Settings remain unknown until another report after a change.

#### Timing

See the profile table. HA bounds a tap and supports renewable motor holds.
Preset recalls are single writes; the app's save gesture becomes a confirmed
HA action rather than a delayed long press. No UI reload or dialog timer adds
BLE traffic.

#### Notifications

There is no polling or refresh query. Settings require unsolicited receiver
notifications on the current connection. Disconnect clears connection-scoped
state, and callbacks from an older connection cannot republish it.

#### Services

For EB803, `timed_move` motor `back` controls the left back; `right_back` controls
the right back and `feet` controls the common feet. The left back retains its
explicit label and the `left_back_up` / `left_back_down` held controls.

The shared `set_alarm` action exposes EB803's two slots and wake modes 1 (Basic)
and 2 (Pro). A current-link report of both slots is required because every write
carries both. Enabling requires at least one weekday; schedules on overlapping
weekdays must be more than 20 minutes apart (the app compares within the day,
without wrapping midnight). Turning one off preserves both records and clears
only its enabled flag. There is no deletion or bed clock-sync command.

Phone-local alarms can instead be created with Home Assistant automations.
The integration does not reproduce phone preferences or its process lifetime.

#### Evidence

Based on Flexispot 1.1 (2). Hardware behavior remains unverified.


### GhostBed

**App:** [GhostBed](https://play.google.com/store/apps/details?id=com.loctek.ghostbed) 1.3 (4), `com.loctek.ghostbed`

**Status:** Not yet tested

#### Setup

Select **GhostBed app**. Case-sensitive name substrings `W_LeGe` and `GhostBed`
suggest this route; a shared name does not identify the product. Saved addresses
and manual entry do not require a name match. There are no model, PIN or split

percentage sensor is created.

#### Controls

Use the native movement, preset, memory, light, massage and anti-snore controls.
Save Sleep uses a confirmed button; memory saves use the standard confirmed
save actions. Anti-snore offers the app's home on/off control and its left-side
settings switch, sensitivity and target selector. Target labels are settings,
not measured motor angles. The two controls intentionally differ when the bed
reports only the other side enabled. Home changes preserve both raw packed codes;
left settings edits use the app's default peer level rather than adding a right
control. Invalid reported pair codes retain the last valid left setting and
remain visible in raw diagnostics.

#### Timing

See the generated table above. A movement release always cleans up the original
connection after a started write settles, including cancellation or failure.
A replacement connection never receives an old command or STOP. Massage sliders
send the relative difference from a current reported level; a new report is
required before another edit. UI-only drag/cancel gestures and save press timers
are represented by explicit HA value and confirmed save actions.

#### Notifications

The shared parser accepts the current state opcodes with header/footer and length
guards, without adding a response CRC check. The low light nibble drives light
state. Alarm banks 0 and 8 update separate pairs; other banks retain prior alarm
records. Signed Java division/remainder at offsets 4 and 15 is retained. These
fields describe massage and snore state, not motor position.

State is applied as soon as it arrives. The phone app's two-second settings-widget
refresh delay does not delay HA parsing or home state. Raw notifications and a
raw status diagnostic sensor remain available, including the light-only opcode
that the current app screen does not consume. Disconnect clears link-scoped
state; callbacks from a replaced controller cannot update its successor.

#### Services

Use `adjustable_bed.set_alarm` with explicit slot 1–4, repeat weekdays and
`wake_mode_1` (Basic) or `wake_mode_2` (Pro). Turning off without a time clears the enabled bit while retaining the record.
Supplying a time, repeat days and wake mode with `enabled: false` edits a disabled
record without temporarily enabling it. Both alarm-bank reports are required before editing;
unknown records are never silently replaced with empty slots. The alarm sensor
shows the four records. Confirmed Delete alarm buttons compact surviving records
and pad empty slots, writing both pairs with the listed gap. A cancelled or
partially failed write leaves those records unknown until reports arrive.

An alarm cannot share a repeat day with another nonempty record within 30 minutes,
including an inactive record and the exact 30-minute boundary. The comparison
does not wrap midnight. `adjustable_bed.sync_clock` sends HA local time using
