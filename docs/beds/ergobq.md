# ErgoBQ BED

**Status:** Not yet tested on hardware.

**Credit:** Reverse engineering by [kristofferR](https://github.com/kristofferR/ha-adjustable-bed)

## Known Models

ErgoBQ electric-bed products selected by the product IDs in the profile table.
The shared Nordic UART service alone does not identify an ErgoBQ bed.

## Features

| Feature | Supported |
|---------|-----------|
| Motor Control | Head, legs, and serial-selected motor 3 and waist |
| Position Feedback | Reported native target values, without inferred degrees or percentages |
| Memory Presets | Two memories; recall, save and scene-default restore |
| Massage | Head and legs, intensity, mode, timer and parameter-dependent synchronization |
| Lights | Underbed on/off, brightness, RGB and auto-off timer |
| Schedules | Complete custom or DIY records, including explicit enable, disable and delete |
| DIY | Run saved modes, supply an existing app program, terminate and report remaining time |
| Split Controls | A/B/AB route and directional force sync on one receiver; no HA paired conversion |
| Diagnostics | Named fault flags, bed identity and sync partner state |

The app's third motor has conflicting back/headrest labels. The integration
calls it **Motor 3**. Target limits are app UI bounds, not calibrated hardware
travel. Do not interpret unitless targets as degrees or percentages.

### Framing and checksum

Frames contain magic `55 AA`, version zero, one command byte, a big-endian
payload length, payload and big-endian CRC16. CRC starts at `FFFF`, uses the
reflected `A001` polynomial and has no final XOR. Outgoing payloads are limited
to 512 bytes. A DP is an ID byte, type byte, big-endian value length and value.
Types are raw, boolean, signed BE32, UTF-8 and one-byte enum.

Multiple DPs preserve the supplied map order. The Android HashMap does not
promise a wire order. Directional force sync always includes both the AB route
and direction in one message. DIY control includes DP60 only when an explicit
nonempty program is supplied; its control DP61 may precede it.

### Responses

The bounded stream assembler checks framing, version, length and CRC, retains
partial frames and recovers later complete frames. An initial callback without
both magic bytes is discarded, matching the app. CMD05 reports decode typed DP
values; the last duplicate DP wins. Partial or overflowing TLVs are rejected.

Motor values, massage settings and remaining time, light settings, known fault
bits, bed identity and partner flags update native entities. Partial massage
edits require a complete current zone report. Both zones are written only when
massage sync is enabled **and their current parameters match**; otherwise only
the requested zone is written. Values from an old BLE connection are ignored.

CMD01 metadata TLVs are parsed without assigning unverified device-info labels.
DP60 supports the fixed segment parser and a length recognizer for optional TLV
segments. The complex DP41 collection parser is unavailable. Schedule writes
always use complete caller-provided records and never merge an inferred cache.

### STOP and release behavior

A held motor sends its absolute target once, then DP5 true when the gesture
ends or is cancelled. A submitted write settles before cleanup. Release is
bound to the original connection and uses a fresh cancellation event; it is
never replayed on a replacement link. Standalone target numbers are one-shot
absolute requests, like an app tap. Presets and settings add no extra STOP.
HA's short cover action holds for one second; an explicit held action uses its
requested duration and the scheduler's safety ceiling.

No physical STOP-latency or disconnect-failsafe guarantee is established.

## Profiles

### ErgoBQ BED profile

**App:** [ErgoBQ](https://play.google.com/store/apps/details?id=com.bestqi.ergobqandroid) 1.8.1 (27), `com.bestqi.ergobqandroid`

**Status:** Not yet tested on hardware.

#### Setup

Choose **ErgoBQ BED app** and the explicit BED product ID. An exact product ID
in service data can refine discovery; no generic UART name or UUID is accepted
as product identity. The optional serial is the first six bytes of manufacturer
data under company `FFFF`, written as hex. Blank uses the app's two-motor default.
The separate MindLax mattress is not a BED product.

Supply an existing channel stamp, or leave it blank when unused. Account login
and credential retrieval are not provided. The stamp and serial are redacted
from diagnostics, including fragmented authentication writes.

Notifications use Home Assistant's Bluetooth stack and negotiated MTU. The
controller waits for the proven channel authentication response before sending
controls, RTC calibration and the initial feature/full-state queries. A rejected
or timed-out authentication fails closed. No Bluetooth bond or Android-specific
MTU-request API is added.

#### Controls

Use native covers for held motion, unitless numbers for absolute targets,
buttons for scenes and directional sync, switches for massage sync and child
lock, and the RGB light for lighting. Scene saves/restores require confirmation
in the card. Side selection and maintenance controls are opt-in.

RTC and feature-query transmission does not establish device acceptance.
Metadata/unlink responses use their own command and nonempty-payload contract.
An unlink response alone is not interpreted as a success code; the integration
releases that connection and requires fresh authentication.

#### Notifications

All caches, callbacks and pending waits belong to one connection and are
invalidated when it ends. Unrecognized DPs and opaque command payloads do not
create raw controls or sensors.

#### Services

- `ergobq_scene`: recall, save or restore any named scene.
- `ergobq_massage`: send complete parameters for one zone. Partial entity edits
  require reported current parameters.
- `ergobq_schedule`: supply task, status, repeat weekdays, time and a complete
  custom action or DIY payload. Delete uses a complete record with status zero.
  A synchronized custom massage record requires equal head and leg parameters.
- `ergobq_diy`: select a saved mode, optionally supplying its existing app
  `program_hex`. This is the app's explicit program input, not a raw BLE action.
  No vendor catalog is fetched or invented.
- `ergobq_unlink`: explicitly send association phase 2 or 3. Account changes
  are not performed. `sync_clock` uses the local HA time and offset.

See [Actions and automations](../SERVICES.md#ergobq-bed-actions) for parameters.

#### Evidence

Based on ErgoBQ 1.8.1 (27). Hardware behavior, target calibration, credential
availability and real-world release latency remain unverified. The full
schedule collection parser and broader app lifecycle/metadata reconciliation
remain incomplete. Wi-Fi, bed network administration, cloud/accounts,
OTA/DFU, audio playback, dedicated mattress and unrelated companion products
are outside this integration.
