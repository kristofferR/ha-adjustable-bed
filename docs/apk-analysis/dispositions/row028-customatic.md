## Retained behavior and explicit adaptations

All three profiles use the exact six-byte mask builder and physical GATT role. Clarity and Jerome’s retain eight safe two-axis motor states; Remedy retains 26 safe three-axis states. Clarity and Remedy each retain all 31 nonempty memory subsets, including Flat + ZG and Flat + ANTI. Named Program/save/reset controls, native stateless light toggle, all motor axes, elapsed-time ceilings and protocol cleanup are exposed through registered actions and entities. Jerome’s fresh Flat sends the alternate frame three times; its restored generic Flat remains a separate one-write button. Two physical selected beds receive identical payloads through explicit HA paired/multiple-device targeting, with no invented packet-side selector.

The app inherits an unspecified runtime Android write type. HA validates the writable characteristic and selects acknowledged writes for `write`, otherwise unacknowledged for `write-without-response`. This is a documented host policy, not proof of the app’s runtime ATT mode or hardware semantics. Shared names and UUIDs cannot identify the retail app; setup requires one explicit fixed profile and physical address. DIS strings are display-only and do not select capabilities.

The five Device Information UUIDs, order, UTF-8 replacement decoding, empty-string cache semantics and whole-batch retry when any field is missing are retained. Android posts callbacks at nominal 0/120/240/360/480 ms and can overlap batches. HA serializes reads with minimum 120 ms spacing, bounds each read and isolates physical-device metadata. Fixed Android posted offsets and concurrent/cross-session callback leakage are separate platform exclusions, not missing reads.

HA starts an explicitly selected composite mask immediately on one 120 ms refresh lane. It does not replay pointer-event phase, duplicate chains, counter underflow, unsafe same-axis opposite directions, mutable delayed-release races or stale command resumption after reconnect. Every motor cover uses the wildcard scheduler resource because STOP clears the shared command mask for that physical bed. A Stop from another axis therefore preempts the running held stream. Motor cleanup sends a fresh zero after 100 ms, outside the refresh deadline and protected from cancellation. Memory refresh ends without an invented release frame; flat and light remain one-shot. Android 2700 ms Saved/Reset toasts, including stale confirmation callbacks, are UI state and do not prove hardware acceptance. The named save buttons use that documented duration without inferring a hardware acknowledgement.

No reachable position notifications, massage, authentication, custom settings, firmware, WiFi/cloud or numbered memory slots are inferred. Dead SDK wrappers are distinguished from identical masks that remain reachable through the memory page. Factory/configuration, exact entity surfaces and profile transitions are covered by current tests.
