## Deliberate Home Assistant treatments

Android touch artwork, wheel delays/debounce, uninitialized FF alarm fields, stale callback-vs-command state and wrong-memory selector paths are not alternate bed features. HA exposes the complete validated alarm time/memory atomically, retains the disabled schedule, persists Cherish intent, and never restores phone audio or invents a receiver ACK. Partial/invalid feedback is diagnostic only. All app edge cases remain linked above and in the complete local ledger.

Queue admission, no-write, readiness, callback failure, descriptor failure, timeout, cancellation and recovery are separate paths. HA uses its existing serialized command lane, complete GATT readiness and transport recovery instead of Android numeric errors, queue caps and cache-reflection implementation. No identical bytes are used to assert equivalent lifecycle. New focused tests cover actual profile rejection, cancellation, subscription failure, retry after link failure and release behavior; shared coordinator/paired/service tests cover command locking and routing.

WiFi, SSID/passwords, provisioning, bed-network administration, cloud/account services, dead helpers and unrelated Android infrastructure have explicit X-row exclusions. None is implementation debt. HA Bluetooth adapter/proxy and setup infrastructure remain supported.
